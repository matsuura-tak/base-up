# 第1部 発見（何を、なぜ作るか）

## 1. 紹介文
ソフトウェアエンジニアが、登録0秒・環境構築0分でブラウザを開くだけで、システム設計の「順序・副作用・境界値制御」と未知の数値を導く「フェルミ推定の因数分解」を80〜90年代レトロアーケードの手触りで試せる Web ゲームを公開します［推測］。1問に15〜30分かかる対策書籍やコード提出サイト［公開情報 <https://www.codingame.com/start/>］［推測］と比べ、3手・3スロットの選択と視覚シミュレーションにより1ステージ約2〜3分（約5〜10倍の速さ）で破綻箇所や二重計上の罠を把握できます［推測］。年額一括課金（月額換算 ¥1,625/月）［公開情報 <https://brilliant.org/premium/>］や月額 $34.99［公開情報 <https://www.quantable.io/pricing>］、買い切り ¥800［公開情報 <https://apps.apple.com/jp/app/human-resource-machine/id1005098334?see-all=reviews>］の既存サービスに対し、全19ステージ・解説・5軸の思考特性ランク算出まで ¥0 で完結します［実データ］。

## 2. 中心の Job
- Job ストーリー（1つだけ）：技術面接の対策中や開発業務の合間の5〜15分に自分の設計判断や概算の感覚を確かめたいとき、環境構築や長文読解なしに要素の組み合わせ順序・制約の境界・桁の因数分解を試してどこで破綻したかをその場で目で見て確かめたい。そうすれば、退屈な暗記に頼らず楽しみながら自分の思考の弱点に気づき、設計議論や未知の数値見積もりで筋の通った仮説を組み立てられるようになる［推測］。
- 機能の面：登録・決済なしで開始後10秒以内に問題へ入り、1問3分前後で順序・制約と桁分解を試行して破綻理由と強み・弱点を確認できる［推測］。　気持ちの面：無機質な試験問題や英語長文で消耗せず、音と視覚変化の手触りで没頭できる［推測］。　人の目の面：遊びながら実務・面接に効く思考力を鍛え、思考特性ランクを知的な話題として共有できる［推測］。

## 5. 機会と解決
- 根（成果）：初回訪問での診断カルテ到達率（両モード各1ステージ以上クリア＋カルテ表示割合）
- 機会（顧客の言葉で3つ以上）：
  - O-1：「5〜10分の空き時間では、アカウント登録や環境準備、英語問題文やスマホでの見づらさだけで始める前に閉じてしまう」［公開情報 <https://apps.apple.com/jp/app/brilliant-learn-math-coding/id913335252?see-all=reviews>］［公開情報 <https://apps.apple.com/jp/app/human-resource-machine/id1005098334?see-all=reviews>］
  - O-2：「制約違反や桁ズレで失敗したとき、自分のどの順序や仮説が罠だったのかその場で見えず投げ出してしまう」［公開情報 <https://apps.apple.com/us/app/human-resource-machine/id1005098334?see-all=reviews>］［公開情報 <https://www.quantable.io/pricing>］
  - O-3：「単発問題を1問解いても自分の思考特性の強み・弱点が全体で見えず、別モードまで続けて試す動機が湧かない」［推測］
- 選んだ機会と理由：O-2 を主軸に O-1・O-3 を連動して解く。開始摩擦をなくしても（O-1）、失敗時の納得感（O-2）と自己診断の報酬（O-3）が揃わなければ2モード完走に至らないため［推測］。

## 10. やらないこと（非目標）と、はまりやすい所
- やらないこと（理由を1行ずつ）：
  - パックマン等の迷路ドットイートアクションゲームの実装：反射神経ゲームになり思考パズル・数値推定の本質から外れ、初期構想の禁止要件にも該当するため［実データ］（`docs/idea-seed.md`）。
  - バックエンド API（`backend/`）・DB・ユーザー登録・ログインの実装：初回開始までの摩擦を0秒にし、インフラ運用費¥0・オフライン動作を実現するため［実データ］。
  - 外部音声ファイル（`.mp3` / `.wav` 等）や外部画像 CDN への依存：通信エラーや読み込み遅延を防ぎ、Web Audio API とブラウザ描画だけで単体完結させるため［実データ］。
  - ユーザー操作前の自動音声再生（オートプレイ）：ブラウザの自動再生ブロックによる例外と、職場・移動中の音出し事故を防ぐため［推測］。
  - 未実装のダミーボタンや「Coming Soon」ステージ枠の配置：体験の信頼を損ね、完了条件に反するため［実データ］（`docs/idea-seed.md`）。
- はまりやすい所と避け方：
  - 『3-ACT COMBINATOR』の高難度ステージ調整で「解なし」または「どの順でもクリアできる」状態になる罠：ステージ定義データに対して全順列（最大 `7×6×5 = 210` 通り）を走査する単体・受け入れテストを必須化し、正解数が `1以上` かつ全順列の `50%以下` であることを自動検証する（AC-4）。
  - 『FERMI BLASTER』が統計暗記クイズや罠なし問題になる罠：ピンポイント数値一致でなく対数誤差（`|log10(推定値/基準値)|`）と罠カード（二重計上・単位桁ズレ）の有無で判定し、全9ステージで `PERFECT ORDER` が `1通り以上` かつ全組み合わせの `50%以下`・罠カード `1枚以上` であることを自動検証し、基準因数分解式と罠カードの解説を必須化する（AC-8、AC-9、AC-19）。
  - レトロ CRT・ネオン演出による文字コントラスト不足と画面揺れ酔い：本文・数値のコントラスト比を WCAG 2.2 AA（4.5:1 以上）に保ち、`prefers-reduced-motion: reduce` 時は画面シェイク振幅を `0px` にする（AC-17、12）。

### 思考力診断カルテの算出規則（AC-10・AC-11・AC-12・AC-20 共通基準）
プレイ履歴から算出する `5軸` 整数スコア（各 `0`〜`100`、小数第1位を `Math.round` で四捨五入）および総合認定ランクの規則を以下に固定する。公式クリア記録および試行回数集計はモード1の `RUN` 実行とモード2の `FIRE` 実行のみを対象とし、モード1の `STEP`（1ステップ検証）はクリア記録および試行回数に加算しない。

| 区分・軸名 | 参照するプレイ指標 | 算出式（整数 `0`〜`100`）と境界規則 |
|---|---|---|
| 仕様読解力（モード1） | クリア済みステージ数 $C_1 \in \{0..10\}$、初回 `STAGE CLEAR` 到達時の累積 `RUN` 回数 $a_s = 1$ であった一発クリアステージ数 $F_{\text{count}} \in \{0..C_1\}$（初回クリア確定後は再プレイで上書きしない） | $C_1 = 0$ のとき `0`。$C_1 \ge 1$ のとき `Math.round(40 * (C_1 / 10) + 60 * (F_count / C_1))` |
| 順序構築力（モード1） | クリア済みステージ数 $C_1$、各クリア済みステージの初回クリア時 `RUN` 回数 $a_s \ge 1$ から求める効率値 $e_s = \max(0, 1 - 0.25 \times (a_s - 1))$ の平均 $\bar{E}_1 = (\sum e_s) / C_1$ | $C_1 = 0$ のとき `0`。$C_1 \ge 1$ のとき `Math.round(30 * (C_1 / 10) + 70 * E_bar_1)` |
| リソース制御力（モード1） | クリア済みステージ数 $C_1$、モード1全ステージの累積 `RUN` 回数 $R_1 \ge 1$、結果が `CRASHED` となった累積 `RUN` 回数 $K_1 \in \{0..R_1\}$ | $C_1 = 0$ のとき `0`。$C_1 \ge 1$ のとき `Math.round(30 * (C_1 / 10) + 70 * (1 - K_1 / R_1))` |
| フェルミ概算センス（モード2） | クリア済みステージ数 $C_2 \in \{0..9\}$（`PERFECT ORDER` または `GOOD RANGE` 達成）、各クリア済みステージの最高判定係数 $q_s$（`PERFECT ORDER` 達成済は `1.0`、`GOOD RANGE` のみは `0.6`）の平均 $\bar{Q}_2 = (\sum q_s) / C_2$ | $C_2 = 0$ のとき `0`。$C_2 \ge 1$ のとき `Math.round(30 * (C_2 / 9) + 70 * Q_bar_2)` |
| 仮説精度（モード2） | クリア済みステージ数 $C_2$、モード2全ステージの累積 `FIRE` 回数 $F_2 \ge 1$、罠カードを `1枚以上` 選択して `FIRE` した累積回数 $T_2 \in \{0..F_2\}$ | $C_2 = 0$ のとき `0`。$C_2 \ge 1$ のとき `Math.round(30 * (C_2 / 9) + 70 * (1 - T_2 / F_2))` |
| 総合認定ランク | $C_1, C_2$ および上記5軸整数スコア $X_1..X_5$ の平均四捨五入値 `overallScore = Math.round((X_1 + X_2 + X_3 + X_4 + X_5) / 5)` | **$C_1 = 0$ または $C_2 = 0$ のとき**：`UNRANKED`（未解放）。**$C_1 \ge 1$ かつ $C_2 \ge 1$ のとき**：`90〜100` = `S+`、`80〜89` = `S`、`65〜79` = `A`、`50〜64` = `B`、`0〜49` = `C` |

## 12. 非機能要件
- 速さ：ローカル本番ビルド配信時（CPU スロットリングなし・高速回線相当）のナビゲーション開始から初期3導線が操作可能になるまで `1.0秒以内`、Lighthouse 計測および本番 RUM の75パーセンタイルで `LCP <= 2.5秒`、`INP <= 200ミリ秒`、`CLS <= 0.1` を満たす［公開情報 <https://web.dev/articles/vitals>］。各ステージの `RESET` 応答は `0.2秒以内`、通常時のシミュレーション再生完了は `3.0秒以内`（`prefers-reduced-motion: reduce` 時は `1.0秒以内`）とする［推測］。測り方：G2/G3 で Playwright（Navigation Timing / `performance.now()` 計測・再生時間検証）と Lighthouse で計測し、公開後はホスティング RUM で計測する（詳細なバンドル予算は G1 で `tech-lead` が ADR に定義・要確認）。
- オフラインや通信エラーのとき：外部 API・外部音声アセット・動的チャンク分割に依存せず全19ステージのロジックと解説データを初期バンドルに内蔵し、初期読み込み完了後の `offline` 状態でも未捕捉 JS 例外 `0件`・通信失敗停止 `0件` で全機能が動作する（AC-14）［実データ］。本番公開時に匿名解析を有効化した場合も、解析リクエスト遮断・失敗時の未捕捉例外 `0件` とする［推測］。測り方：Playwright の `context.setOffline(true)` 完走テストおよびネットワーク遮断（`page.route` abort）時の `pageerror` 監視（`0件`）で検証する。
- セキュリティとプライバシー：氏名・メールアドレス・アカウント ID・Cookie 識別子等の個人データ収集項目 `0件` とし、プレイ進捗・ミュート設定・コホート算出フラグは端末の `localStorage`（不可時はメモリ）にのみ保持してゲーム進行データ本体の外部送信リクエスト `0件` とする［実データ］。測り方：Playwright のネットワーク監視（初期配信後の外部オリジン通信 `0件` および `context.cookies()` の Cookie 発行 `0件`）ならびに G4 での OWASP ASVS L1 監査・HTTP セキュリティヘッダー検査（`curl -sI`）で検証する。
- アクセシビリティ：WCAG 2.2 レベル AA 準拠として、全画面・全状態で自動監査違反 `0件`、通常テキストのコントラスト比 `4.5:1` 以上・大文字および UI 部品 `3:1` 以上（ライト／ダーク両テーマ。配色トークンは G1 で `designer` が定義・要確認）、全操作要素の押下領域 `24x24px` 以上、幅 `320px`・`1280px` × 文字拡大率 `100%`・`200%` の4条件すべてで横はみ出し幅 `0px` かつ要素重なりによる押下不能 `0件`、`prefers-reduced-motion: reduce` 時の画面シェイク変位 `0px`、およびキーボード操作のみでの全モード完走率 `100%` を満たす［実データ］（`docs/org/gates.md`）。測り方：`@axe-core/playwright` スキャン（違反 `0件`）、Playwright レイアウト計測・キーボード完走テスト、および5通りスクリーンショット監査で検証する。
- 言語：既定の表示言語は日本語（`ja`）とし、英語（`en`）文言辞書とのキー不一致（欠落キー・余剰キー・空文字列）`0件` および言語切替時の未翻訳キー露出 `0件` を満たす［実データ］（`docs/idea-seed.md`、`docs/org/gates.md`）。測り方：G2/G3 の単体テストによる `ja` / `en` 辞書キー完全一致検査（差分 `0件`）および Playwright での `ja` / `en` 表示切替スクリーンショット検証で確かめる（画面上の切替露出方針は 18 の Q-3 で確認）。
